# Trial expiry and an existing Community shop

Open **Settings → Cloud Sync → Manage cloud connection** to see the last successful sync and the number of records waiting to upload. A confirmed trial expiry displays the following message.

> Your cloud trial has ended. You can continue using Posnic Community offline. Cloud sync is paused.

Sign in locally on the computer that already holds the shop. Only locally available records can be used offline. Keep the same shop, its device connection and local backups. An incomplete initial download can leave records available only in the hosted shop. The public [Community and data-transfer page](https://www.posnic.com/api/trial-ended) explains the support process.

An eligible owner can use the secure extension link sent to their registered email. After an extension or verified renewal, choose **Check cloud access**. If the device needs new credentials, choose **Sign in to this cloud shop** and authorize the existing shop in the browser. A confirmed active connection resumes ordinary sync from its saved checkpoints. More recent edits and a large backlog can take several cycles to settle.

The automatic check normally runs after an hour plus up to fifteen minutes of jitter. Connection or service failures progressively increase the delay. Separate desktop windows use the same local agent. Refreshing the status panel reads the local agent. An administrative restriction requires support review.

## Release acceptance

Use a disposable paired profile for these checks. Record its initial pending count, a synthetic item quantity, and the cloud request counters. Expire the trial while the shop is open. Save a cash sale locally, close the desktop normally, reopen the same profile, and sign out and back in. The pending count and original sale must survive. Confirm that only the lightweight entitlement check reaches the server during the paused restart. Restore the trial through the registered test mailbox. Choose **Check cloud access**, wait for the backlog to drain, and compare the sale identifier, total and stock on both sides. Repeat on a second, active test shop and with an administrative hold. An old agent may lack the check button until the authenticated component update is installed.

Signing and publication follow the existing desktop release process. The private agent is delivered separately through the authenticated signed component channel.
