# Branch wording profiles

## User workflow

Super admins open Settings → Language & labels, create a named profile, choose
its base language, search existing labels and enter replacements. Save draft
does not affect users. Save & publish assigns the revision to the checked
branches. Clearing every branch and publishing removes that profile's
assignments. Restore default removes an individual replacement. There is no
preview stage.

The English grouping controls update exact registered Takeaway/Product/Products
labels and the listed related phrases. They do not perform substring replacement
on business data, customer notes, product names or other languages.

## Persistence and upgrades

The `settings` collection stores one tenant-scoped document with
`kind: wording_profiles` and schema version 1. Its deterministic ID is derived
from the license ID. Drafts, immutable published revisions and branch/locale
assignments are changed atomically with revision-based compare-and-swap.
Concurrent saves fail with 409 rather than overwrite another administrator.

Overrides are keyed by stable IDs (`posnic.lang_takeaway`), not by translated
text. Shipped JSON files remain the defaults; installers never write tenant
overrides into them. New labels inherit standard wording, removed labels keep
their saved overrides, and reintroduced IDs reuse their overrides. Never reuse
an ID for a different meaning. Renaming an ID requires an explicit reviewed
migration; there is no fuzzy automatic migration.

Values are plain text. Replacement placeholders must match the label contract.
On a later contract change an incompatible override is skipped and the standard
label is used. Unsupported profile schema versions are rejected, allowing clients
to retain their last compatible cached bundle. The editor limits profiles to 30,
overrides to 2,000 per draft and the document to 4 MiB; history is never silently
discarded to meet the limit.

## Extension contract

Installed extension packages may ship trusted JSON manifests under
`api/src/catalogs/extensions/<extension-id>.json`:

```json
{
  "extensionId": "rooms",
  "labelSchemaVersion": 1,
  "labels": [
    {"id": "ext.rooms.charge", "defaults": {"en": "Room charge"}}
  ]
}
```

Foreign namespaces and duplicates are rejected. Extensions render through the
same translation resolver using their full namespaced key and a bundled default.
Removing the manifest hides its labels from resolution but retains overrides.
This is an installed-package contract, not a public endpoint for uploading code
or registering arbitrary untrusted extensions.

The core catalog is generated by `scripts/build-wording-catalog.js`, included
in API runtime preparation, and checked with its `--check` option.

## Authority and offline delivery

Cloud is the write authority for paired desktop installations; paired tills
are read-only for profile management. Standalone installations manage their
own profile. Management routes require super_admin and reject API keys.
Bundle reads require authentication, tenant membership and branch access.

Profiles use the existing global `settings` sync lane. No new collection or
sync endpoint is required. Assignments and revisions travel as one document,
using existing Date/ObjectId EJSON serialization and updated_date checkpoints.
Old retries cannot replace a newer document. Business order types and IDs remain
unchanged: Parcel is presentation wording, while Takeaway remains canonical.

Clients cache by server/shop, branch and language (desktop also includes user).
Failed refreshes preserve the last valid bundle. Refresh occurs on foreground,
network restoration and a foreground one-minute interval. Publishing means
saved at the authority, not acknowledged by every device. Offline devices apply
the change after their normal sync and refresh.

## Current rendering coverage

- POS shared translation runtime: registered UI labels, including English.
- Receipt-designer labels already using that runtime, plus order-type wording.
- Kitchen-ticket order-type wording.
- Sales invoice PDF item, quantity, price and amount headings. This generator
  currently renders in English and resolves the branch's English profile.
- Captain's shared Takeaway/Product terminology mapping, with offline cache.

Legacy hardcoded text and unrelated export/PDF generators are not automatically
rewritten. Machine CSV field names are intentionally unchanged. An extension or
new screen must use registered keys to participate. Reprints currently resolve
the active profile; historical document-specific wording snapshots are not
implemented. Do not advertise universal legacy-document coverage or frozen
historical wording based on this implementation.

## Verification and rollout

`tests/wording-profiles.test.js`, `tests/wording-access.test.js` and
`tests/wording-editor.test.js` cover drafts, assignments, restore defaults,
concurrent edits, authorization and upgrade/extension compatibility. Existing
i18n runtime/coverage tests cover English overrides and translated UI.

Run `scripts/check-wording-sync.cjs` with WORDING_POS_ROOT and
WORDING_GATEWAY_ROOT pointing to matching checkouts. It uses disposable MongoDB
and the actual gateway router: two local till databases, offline reads,
checkpoint resume, tenant separation and stale retry rejection. It never uses
customer databases. This is not a live fleet acknowledgement test.

Deploy API/catalog support before clients. Validate the exact bundled sync agent
with `scripts/prepare-sync-agent.js` for the release checkout. On 2026-10-20,
wording delivery tests and both web builds passed, but available agent checkouts
did not exactly match this checkout's unrelated collection list. Desktop
installer packaging remains blocked until release versions are aligned. No
production deployment or customer profile changes were performed for this work.
