# Books saved-source export

`GET /api/v1/accounting/sales` is an additive read-only contract for an explicitly connected Books client. It requires the existing sales read permission and uses the existing licence and branch filter, rate limiter and typed cursor. Legacy sales endpoints and all checkout/write paths remain unchanged.

`GET /api/v1/accounting/sales/{kind}/{id}` returns one `posnic.sale-source-item.v1` envelope with the same projected record and permissions. Use `string` or `objectId` explicitly; the latter requires 24 lowercase hex characters. A string and ObjectId with the same spelling remain different identities. Missing or out-of-scope records return 404. Books rechecks this endpoint before archiving the reviewed version; a changed revision is held for review. The endpoint does not write to POS or reserve the sale against subsequent changes.

The `posnic.sale-source-page.v1` response contains `data` and the existing `meta.count`/`meta.next_cursor`. Each row has a typed `sourceId`, exact `sourceJson` (`posnic.sale-source.v1`) and SHA-256 `revision` of that UTF-8 string. Selected saved totals/state/currency values are whitelisted; contact information is omitted. The hash detects changed bytes; it is not a digital signature. Missing currency stays missing. This is a current snapshot, not a complete financial event feed. Payments, returns, deleted history, intermediate changes and accounting reconciliation require further implementation before posting.

Synchronization: reads the existing branch-scoped `sales` lane; no new collections, fields, writes or Gateway/agent changes. Offline tills may not yet be represented on another server. No stronger synchronization guarantee is introduced. Roll out the API before expecting Books source-value review; older POS versions continue their existing functionality.

Local validation uses Books `tests/pos-sales-contract.integration.js` against the actual POS router and token resolver with isolated real MongoDB databases. It verifies existing sales pagination, string/ObjectId identities, tenant/branch isolation, scopes, revocation, changed revisions and no Books journals. The POS sender outage/retry integration also passes for both Books editions. Books native UI testing uses fixture source responses; installed POS checkout/payment flows and full POS regression are not established by these checks. Application publication remains held.

The focused isolated POS tooling check passes all 18 existing v1 contract tests and three source export tests (typed identities, canonical revision stability, unchanged saved values and missing-currency behavior). ESLint passes the changed API files. Full checkout/payment and installed-build acceptance remain separate pending gates.

The additive scalar projection also includes saved tax/return-tax, discount/return-discount, partial/pending payment values and source invoice identity. Books uses these for read-only reconciliation warnings. No original sale or payment is changed, and no missing currency is inferred. The snapshot still does not supply complete item-level tax and financial-event evidence for posting.

Selected item identity/quantity/amount/tax fields and version-1 pricing currency are now exported via nested inclusion projection. Item notes, pricing rule details and currency symbols are not exported. Books cross-checks saved currencies and compares line-tax sums; it preserves the existing POS line/header rounding semantics. Existing sales storage and calculation remain unchanged.

The nested inclusion projection also selects Captain allocation IDs/methods/amounts/dates and tender splits, tender-correction IDs/dates/before-after values, and return record IDs/amounts/dates. Staff details, payment references and UPI metadata are omitted. These are saved source activities, not a claim that counter-payment history is complete or a return has been settled. Books treats their identities separately from content revisions and excludes conflicting duplicates from its displayed collection total. No persistence or write behavior changes in POS.

The projection also exports saved bill-discount, coupon-value and loyalty-value amounts, tip amount/inclusion flag, and charge amount/tax/boolean-taxed fields. Coupon codes, loyalty-point counts and charge names are excluded. These are existing saved values: no POS pricing or write behavior changes. Books reconciles item gross + charges - header reductions + rounding against saved payable, keeps stored tax unchanged, and holds missing history or required tax allocation. The focused regression now passes 51 tests across v1, tax engine, sale headers and charge normalization, plus changed-file lint.

## Typed customer references

When either original customer field exists, `sourceJson` includes additive `customerReferences: { version: 1, customerId, legacyCustomer }`. Each field is null, `{ kind: "objectId" | "string", value }`, or `{ kind: "unsupported" }`. Both references retain their original types; conflicting fields are not merged. Raw customer fields are removed from `values` and represented only by this limited typed form so malformed nested contact objects cannot leak through the sales-read export. Names/contact information remain excluded. Missing fields preserve the previous source bytes; adding a reference changes the hash and requires source review. No financial event identity, stored sale or existing checkout/payment endpoint changes.

This reads existing sales-lane fields and introduces no writes, collections or synchronization configuration. The connected server may lag an offline till. Full credit/customer payment history, cross-till convergence and installed export rollout remain open. Books must not infer a receipt from the paid/pending scalar or treat a current mutable wallet transaction as immutable payment history.

Validation for typed references: 52 focused v1/tax/header/charge checks and changed-file ESLint pass. Actual token/router/MongoDB tests confirm scope boundaries, typed reference conflicts, nested-contact exclusion and unchanged stored sale documents. An initial lint failure on a control-character regex was corrected with equivalent character-code checks and rerun. No full checkout, cross-till or installed-export acceptance is claimed.
